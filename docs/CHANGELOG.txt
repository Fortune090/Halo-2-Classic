H2Classic (stage 9, build s10m) - Halo 2's own code as a Windows program (test build)
=====================================================================================

What this is
  H2Classic.exe is the halo2-decompiled source compiled for Windows. It takes the game's starting data and the
  code of the functions the decompilation does not have yet (or has only as unproven drafts) from YOUR unmodified
  v1.0 default.xbe each time it starts, and reads the maps from the Rom folder; it does not run without them.
  Nothing of the XBE, of the console or of Microsoft is in the exe or written to disk.
  Source code: https://github.com/Fortune090/Halo-2-Classic. H2Classic is free software under the GNU General Public
  License, version 3 or later (LICENSE.txt); LICENSES.txt has its notices and those of the code it uses.

New in s10l (build 34): controller vibration, and Increased LODs really applied
  1. Vibration
  The game works out two motor speeds for each controller (from what happens to you: firing, explosions, damage) and
        hands them to the console every time it reads the controllers. H2Classic took them and threw them away, so no
        build so far has ever made a controller vibrate.
  Now they go to the PC controller in the same port, through Windows' controller library (XInput). The Xbox pad's
        left motor is the heavy, slow one and its right motor the light, fast one; XInput's are the same and use the
        same range (0 to 65535), so the game's numbers go across unchanged. The game's own rules still decide when it
        vibrates: nothing with Vibration off in the player's profile, outside a game or while paused.
  Two things are the PC's, not the game's: the motors stop while another program has the focus (the controller
        reads as untouched then too), and when H2Classic closes (window, EXIT, a crash), so a pad is never left
        running.
  Checked here with a stand-in for Windows' controller library that writes down what it is sent: firing the SMG on
        Ivory Tower sent left motor 32768, right motor 39321 while the trigger was held, then 0 when it was let go.
  2. Instanced geometry (and objects) still dropping out at a distance with Unlock Performance
  Increased LODs (from Spooky Ghost) has three parts: instanced geometry never faded out by distance, objects always
        at their most detailed model, shaders at their most detailed level. They were put into the game's source in
        s9q, but two of the three never ran: H2Classic runs some of the game's routines as the XBE's own code
        (where the decompilation only has an unproven draft), and the instance fade routine is one of them; the
        objects' level-of-detail routine is only ever called from another such routine, which calls the XBE's own
        copy. So instances kept fading out and objects kept dropping to simpler models at a distance; only the shader
        part worked.
  Now Spooky Ghost's own two patches go into the XBE's code at the same two places the mod patches on the console:
        the instance fade answers "fully drawn" (an instance is drawn whenever it is in view), and an object's level
        of detail is set to the highest, which the game's own limit then brings down to the most it allows.
  Checked here on Ivory Tower with a counting build: over 240 frames, 7524 instance fades were worked out and 498 of
        them would have faded out or left the piece out - all drawn fully now; every object's level was raised (596 of
        596). The log says "Increased LODs: 2 of 2 places in retail's code go through the layer". I also went through
        every other change made to the game's source for H2Classic (about 50 routines): none of the others sits where
        the XBE's own code runs instead.
  Drawing every far piece and every object at full detail costs some frame time, as on the Xbox with the mod.
  Test launcher: "Increased LODs off (for comparing)" (H2N_LODS=0) and "No vibration (for comparing)" (H2N_RUMBLE=0).
  H2Classic Settings.exe and H2Classic_DLSS.exe are build 33's, unchanged.

New in s10k (build 33): the light on the ground that disappears when you get close (your video, Ivory Tower)
  The overhead lights' patch of light on the ground is drawn in a pass of its own. Near a light, the game also gives
        that pass the light's shadow map: a depth picture the light "sees". For each pixel of floor the console compares
        that depth with the pixel's distance from the light, and multiplies the light by the result: 1 where nothing
        is in the way, 0 where something is. The game only does this for lights near you; farther away the light is
        drawn without the test.
  H2Classic couldn't read a shadow map (its depth format, 0x2e), so that test read 0 everywhere. "Something is in
        the way everywhere" means the whole patch of light was gone, but only near the light, where the game uses the
        test. Your Metropolis capture from build 28 shows it too: the tunnel light's pass reads its shadow map
        (0x82b1b000, format 0x2e), marked "not available". It has been like this in every build so far: shadow maps were
        on the list of things not read yet since the first builds that drew anything.
  Now the pass reads the shadow map's depth and does the console's compare (the game sets "greater": lit where what
        the light sees is farther away than the floor). So the light on the ground should stay when you walk up to it,
        now with the shadows of whatever stands in it (you, crates, pillars).
  Checked here: every variant of the new shader is accepted by Direct3D 9 (256 shaders made in a test that forced the
        compare onto every texture, none refused, none failing this build's own check), self-test 32 of 32. I didn't
        get to one of these lights here, so how it looks is for you to see.
  For comparing: "Lights near you without their shadow map (as build 32)" in the test launcher (H2N_SHADOWMAP=0).
  H2Classic Settings.exe and H2Classic_DLSS.exe are build 32's, unchanged.

New in s10j (build 32)

  Shield recharge rings stuttering while you move (your video)
    The rings are particles of an effect the game starts on your own body when the shield begins to recharge. With
        Unlock Performance, frames between two ticks draw your body and the camera at the in-between moment, and
        what an object carries (its lights, its effects' particles) is moved with it for that frame. Everything on
        your own unit was left out of that in first person. That rule came from Spooky Ghost v2.0.36: there, moving
        your own lights or particle places had upset the first-person arms, and which of the two did it was never
        found. So the rings stayed where the last tick put them, up to a tick ahead of you. Standing still, that's no
        difference. Moving, it's a shake 30 times a second.
    Now the particle places of effects on your own unit move with it too. What your unit holds (your weapon's
        effects) and your lights stay as before. This goes one step past Spooky Ghost's rule, so there's a switch to
        go back (below).
    Checked here in Metropolis with a test build that drained the shield every 5 seconds: the recharge effect is one
        particle system with its places on your body's parts, none of them first-person. Each in-between frame, its
        place now moves exactly as the part it sits on.

  Main menu: EXIT
    A sixth item, EXIT, under SETTINGS. All six show at once, with no scrolling and no arrows. Choosing it closes the
        program the same way the window's close button does: the log ends with its usual closing report. The menu
        wraps as before: up from CAMPAIGN goes to EXIT.
    How: the screen's own definition already asks for six rows, but the game code gives the menu's list only five
        item slots. Now the list has six records and six slots, and EXIT's text is set directly (the screen's string
        list has no EXIT). Three table entries follow the new size: the list's item count, and the code that takes
        the list and the screen apart (retail shares that code with another screen built for five slots). EXIT is
        English in every language.
    Checked here: six rows; up from CAMPAIGN to EXIT; EXIT closes the program; into Campaign, Settings and System
        Link and back; a Metropolis game, then Save and Quit back to the menu, six rows again.

  Your HCM animation fixes (AnimationFixes.cpp), with Unlock Performance only (as you asked: they're seen above 30)
    - Fix 2, the Ivory Tower lifts: ported. The lift (object 0, a machine, as in your fix) runs its position from 0
        to 1 and starts again: 0.986 -> 0.000 every 72 ticks (2.4 s) here. On that tick its pose jumps back a whole
        travel, and blending the two ticks ran it backward through all of it. Now a device whose position moves
        more than half a cycle in one tick is drawn as the tick left it for that tick, along with anything riding on
        it. This works for any looping machine, not only on Ivory Tower. Checked live on Ivory Tower: it catches the
        lift's wrap every time.
    - Fix 3, the rocket launcher's animation (the grenade throw pop): it does apply. The Xbox's shared.map holds the
        same animation data, and all 51 places hold the bytes your fix replaces. They're patched in memory when the
        animation cache loads that data; the map file is never written. Only multiplayer maps use it: no campaign
        map contains this data. Checked with the data from shared.map: 51 of 51 places written, and written again
        after the data is reloaded. Not seen in a live game here yet: that needs a rocket launcher in hand. When it
        happens, the log says "the rocket launcher's animation fix: 51 of 51 places written".
    - Fix 1b (the rocket barrel guard): already in H2Classic. A part that turns more than about 75 degrees in a
        tick is drawn as the tick left it (your threshold, 1 + 2cos < 1.5), for every model.
    - Fix 4 (first-person legs) and Fix 5 (crouch): already in H2Classic. Your body's parts are blended like every
        object's, and the crouch (the biped's +0x2C4 on the Xbox) is one of your unit's blended values.
    - Fix 1 (the 60-tick codec snap): doesn't apply. H2Classic runs 30 ticks a second; that pop comes from sampling
        between animation frames at 60.

New in s10i (your note: settings slow to change when clicking fast)
  The cause: every other quick click was lost. The settings' controls asked Windows for double-clicks, so a second
        click inside the double-click time arrived as a double-click, and the selectors ignored it. Clicking six
        times fast moved a setting three steps. Now every click is a click: six fast clicks move six steps. Checked
        here with real mouse clicks 80 ms apart: build 30 moved 3 of 6, this build 6 of 6.
  Also: settings.ini is written a quarter of a second after the last change instead of at every click. Start Game,
        Exit and closing the window write anything still waiting.
  H2Classic.exe and H2Classic_DLSS.exe are build 29's (s10g), unchanged.

New in s10g (your reports and requests: the prompts and Checkpoint text still wide at 21:9; the bad slowdown in Metropolis;
H2Classic Settings.exe with a Halo-style look and an anti-aliasing quality choice; icons for the three exes)
  HUD text, for real this time. Build 28's fix for the pick-up and vehicle prompts, the messages under them (Checkpoint...
        done) and the status line (WELCOME!, GAME OVER) did nothing. It changed the XBE's copy of the function that draws
        them, but the game never runs that copy: it runs the one compiled from the decompiled source. The fix now sits
        in that source (src/unknown_24c7c1.cpp), around its five text calls. Same method as before, from Spooky Ghost:
        above 16:9 the letters go back to their 16:9 width, in the same place. You confirmed "Hold X to drive Scorpion"
        at 21:9 from my screenshot. Chapter titles were already right in build 28.
  The Metropolis slowdown (your capture of frames 12994-12995). Every draw there went to a light's 512x512 shadow
        map. The console draws a shadow map with its picture surface and its depth surface at the same memory, with
        the picture switched off. Here, one memory could hold only one surface, so the two kept replacing each other:
        both were rebuilt for every draw, 82 draws a frame, each 4096x4096 at render scale 8. That's about 95 of your
        120 ms a frame. The same memory also holds a 128x128 and a 160x120 picture each frame, so those were rebuilt
        too. Now each use of a memory keeps its own surface from frame to frame. The shadow-map pass draws its depth
        into the memory's depth surface and uses a spare picture surface that nothing reads. The log's "picture time"
        line now ends with "surfaces made N a frame", which should stay near 0. Not changed: that light's shadow
        still isn't drawn. The game reads the shadow map in a depth format this build can't read yet, so it was
        missing before too.
  DLSS works. Your log shows the helper ready, the textures open, and 11,109 views through DLSS. Build 28's
        format change was the cause.

        The look follows Halo 2's menus: deep navy, light-blue lines and text, frames with cut corners, and controls
        drawn to match (choices with arrows, toggles, buttons). The font is Windows' own Bahnschrift, or Segoe UI on
        older Windows. Choices change with a click, the mouse wheel or the arrow keys. Same settings, same
        settings.ini, plus the new line below. H2Classic.exe now opens H2Classic Settings.exe on a first start.
        You can delete the old H2Classic Launcher.exe.

          (transformer model), J has a little less ghosting and a little more flicker. Saved as dlss_preset. The
          helper log says which one DLSS was given.
        - FXAA and TAA have no levels, so the line reads "Standard" and is greyed out. (FXAA here is a single pass;
          its "2x/4x/8x" would be supersampling, which Render Scale already does.)
        Checked here: SMAA Low and Medium at the main menu (371 and 380 views, no shader refused); High and Ultra
        are unchanged byte for byte. The DLSS preset couldn't be run here.

How to run it
  Put the game in the folder named Rom, next to H2Classic.exe: default.xbe and the maps folder (the v1.0 game
  folder's contents), or an Xbox disc image (.iso) of the game. Then start H2Classic Settings.exe and press Start Game,
  or start H2Classic.exe itself.
  H2Classic.exe "D:\path\to\Halo2"  names another folder (or a disc image) instead of Rom; a second argument can name
      the default.xbe itself.
  A window opens after a second or two. Close the window to stop (or Ctrl+C in the console).

Controls (only while the game's window is the active one)
  A controller that Windows sees as an Xbox controller works as it is (LB = white, RB = black).
  Keyboard:   Enter = Start        Backspace or Esc = Back     arrow keys = D-pad
              Z or Space = A       X = B       C = X       V = Y       1 = white     2 = black
              W A S D = left stick       I J K L = right stick       Q / E = left / right trigger
              F / G = click the left / right stick
  F12 saves a picture of the current frame (h2classic_frame_NNNNN.bmp).
  F9  (only with H2N_INTERP=3) writes the next 4 seconds of a cutscene into the log, frame by frame.
  F11 describes the next two frames in the log, draw by draw, and saves every surface the game drew into during
      them (h2classic_surface_<frame>_<memory>.bmp, a dozen or so files) and the two frames. This is what to press
      when the picture is wrong: it lets me see which draw went wrong without another round. The game crawls for a
      few seconds while it does this.

Profiles from your Xbox
  The game signs each saved file and calls a file "damaged" when the signature does not fit. The console makes that
  signature with a key held in its kernel (one key, the same in every retail Xbox), mixed with a key in the game's
  own XBE. This build does the same calculation, but the kernel's key is not in the exe and I will not put it in a
  file for you: like the XBE, it has to come from you.
    - The launcher's "Generate Xbox keys.bin file" button makes it from your BIOS image and MCPX boot ROM (s10d).
    - Put it in  h2classic\keys.bin  (next to H2Classic.exe, in the folder you start it from). Accepted forms: 16 bytes (the key);
      32 bytes (the keys.bin that Cxbx-Reloaded uses: the EEPROM key, then this key - the second half is used);
      or the same as 32 or 64 hex digits in a text file.  H2N_CERTKEYFILE=<file> names another file;
      H2N_CERTKEY=<32 hex digits> gives it without a file.
    - With the right key your Xbox profiles load here and what this build saves loads on the Xbox. The method is
      checked here against an independent calculation with made-up keys, not against the real one. Your profile
      (the one in U.7z) was tried here by signing it again with the stand-in key: it loads, with every level listed.
    - Without the file the key is all zeros: an Xbox profile shows as damaged (what you saw), and the log's
      "saved files:" line says so.
    - To check a key before trusting it:  $env:H2N_SIGCHECK="path\to\a profile file from the Xbox"  - the log then
      says THE SAME or DIFFERENT for that file's signature. For the profile in your U.7z the signature begins
      a1375f13 f2a0440d and ends 4755.
    - Profiles made by stage 8 and earlier were signed with a stand-in and show as damaged now, with or without
      the key. Make them again, or copy the Xbox ones in.

  H2N_NETWORK=off   no network, as before s9t (the game is told the cable is out)
  H2N_SHOT=a,b,c    save those frame numbers as pictures;  H2N_SHOT_EVERY=n  every n-th frame
  H2N_KEYS=start@12,a@16   press buttons by themselves at those seconds, or name@f300 at that frame
                    (names: start back up down left right a b x y white black lt rt)
  H2N_KEYFILE=file  read presses from a text file while the game runs: each line added to it is one press (the
                    names above, forward backward strafeleft straferight lookup lookdown lookleft lookright,
                    name*20 to hold it for 20 readings, "shot" to save the frame, "trace" for what F11 does,
                    lthumb rthumb for the stick clicks, "memory" to write h2classic_stop.bin and carry on).
  H2N_WATCH=n       every n ticks, a log line per AI actor and one for the player (place, distance gone)
  H2N_TICK=retail   the game's tick from the XBE's code (experiment; the first-person weapon and body go missing)
  H2N_TABLES=source the 30 table functions new in s9e as the source's drafts again (s9d's behaviour, for comparing)
  H2N_NEWROUTES=off the functions s9f moved to the XBE's code as the source's drafts again (s9e's behaviour)
  H2N_CODEPTRS=retail  the 599 function addresses in the XBE's code left as they are (s9f's behaviour)
  H2N_CERTKEY, H2N_CERTKEYFILE, H2N_SIGCHECK   see "Profiles from your Xbox"
  H2N_INTERP=0      with H2N_UNLOCK: no in-between frames (=2 a line a second about them, =3 a line a frame in a vehicle)
  H2N_HZ=120        with H2N_UNLOCK: this many frames a second instead of the display's refresh rate (a whole part of
                    it - 120, 80, 60 on 240 Hz - is placed on the display's own refreshes). The launcher clears it.
  H2N_LODS=0        with H2N_UNLOCK: the game's own detail levels (no Increased LODs)
  H2N_DRAWDIST=10   with H2N_UNLOCK: the draw distance in tenths of the game's (30 = 300%, the default; 10 = the game's)
  H2N_CARRY=0       with H2N_UNLOCK: lights, particles and effects that moving objects carry stay where the tick put
                    them (for comparing)
  H2N_RENDERONLY=0  with H2N_UNLOCK: the parts only the draw moves (eyes turning to you, some antennas) left to the
                    game's draw (for comparing)
  H2N_AIMLOG=1      a log line ("aim:") for each shot fired near you: where it flew, and how far that is from your view,
                    your aim and the aim of what you ride, in degrees right and up
  H2N_UNROUTE=104150  a weapon's shots fired by the decompilation's draft again (s9q's fix off, for comparing)
  H2N_GFXCACHE=0    every Direct3D 9 setting sent for every draw again (s9r's saving off, for comparing)
  H2N_INTERP=3      with H2N_UNLOCK: F9 in a cutscene writes its next 4 seconds into the log frame by frame
                    The launcher clears the switches above: set them in PowerShell and start H2Classic.exe directly.
  Sound (the other prompt's sound engine, s9p):

  H2N_SOUNDWAV=1    also record the mix to h2classic\h2classic_sound.wav (about 11 MB a minute)
